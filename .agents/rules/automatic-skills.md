# Autonomous Skill Activation Policy

กฎและระเบียบปฏิบัติอัตโนมัติสำหรับการเลือกใช้ Skills ในทุกสถานการณ์การพัฒนาของโปรเจกต์นี้:

---

## 1. กฎการหยิบใช้ Skill อัตโนมัติ (Automatic Trigger Matrix)

เมื่อพบสถานการณ์ต่อไปนี้ AI จะต้องหยิบใช้และปฏิบัติตามแนวทางของ Skill ที่เกี่ยวข้องทันทีโดยไม่ต้องรอให้ผู้ใช้สั่งซ้ำ:

| สถานการณ์ที่เกิดขึ้นในคำสั่งของผู้ใช้ | Skill ที่ต้องเปิดใช้ทันที | แนวทางปฏิบัติหลัก |
| :--- | :--- | :--- |
| **1. ปรับแต่งหน้าตา, ออกแบบ UI/UX, ทำ Responsive, จัดลำดับหน้าจอ** | `modern-web-craft` | - ออกแบบสไตล์ Modern Minimal Glassmorphism<br>- จัด Visual Hierarchy ให้เข้าใจง่ายใน 3 วินาที<br>- ใช้โทนสีประจำสถาบัน (สกจ. / จ.ว.) อย่างลงตัว |
| **2. เจอบั๊ก, หน้าจอเพี้ยน, ขึ้น Error (404/500), ฟังก์ชันทำงานผิดพลาด** | `systematic-debugging` | - ทำตาม 4-Phase Root Cause Analysis<br>- ตรวจสอบ Log และสาเหตุที่แท้จริง ไม่เดาสุ่ม<br>- แก้ไขเฉพาะจุดและทดสอบ Regression Check |
| **3. ได้รับโจทย์ใหม่, ต้องการเพิ่มฟีเจอร์, มีความต้องการที่ยังไม่ชัดเจน** | `brainstorming` | - ตั้งคำถามเพื่อสรุป Requirement ให้ชัดเจน<br>- สำรวจ DB Schema และโครงสร้างเดิม<br>- นำเสนอทางเลือก Option A / B พร้อมข้อดี-ข้อเสีย |
| **4. มีงานที่ต้องทำหลายขั้นตอน, ปรับปรุงสถาปัตยกรรมใหญ่, Migration** | `writing-plans` | - แตกงานออกเป็น Task ย่อยๆ<br>- กำหนด Verification Criteria และวิธีทดสอบทุกขั้นตอน |
| **5. ก่อนสรุปงาน หรือเมื่อแก้ไขโค้ดเสร็จสิ้น** | `requesting-code-review` | - รัน Syntax Linter (`php -l`) ทุกไฟล์<br>- ตรวจสอบความปลอดภัย (XSS, CSRF, Session, SQL Injection)<br>- ทดสอบ HTTP Response Status 200 |
| **6. พัฒนาระบบคำนวณสถิติ, ข้อมูลแบบสำรวจ, หรือระบบความเสี่ยงสูง** | `test-driven-development` | - กำหนด Test Case ล่วงหน้า<br>- ทำตาม Red -> Green -> Refactor cycle |

---

## 2. มาตรฐานการสื่อสารกับผู้ใช้ (Communication Standard)
- สรุปผลการทำงานด้วยภาษาไทยที่สุภาพ กระชับ ชัดเจน
- ทำ Markdown Links ไปยังไฟล์ที่มีการแก้ไขเสมอ (เช่น `[filename](file:///...)`)
- ระบุสาเหตุและผลลัพธ์ของการปรับปรุงให้ผู้ใช้เข้าใจง่าย
